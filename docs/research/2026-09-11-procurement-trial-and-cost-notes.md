# QuotePlate employee/supplier trial and cost notes

Prepared **11 September 2026 (India, IST)**. Status: **proposed protocol; no participants tested and no outcomes measured**. Read alongside the [competitive review](india-restaurant-procurement-competitive-review.md). The implementation baseline is the [README](../../README.md) at `f9a2ab6`; a deployed revision has not been verified in this research task.

## Short trial for people with limited software experience

Recruit a small formative group, for example four restaurant employees who normally use paper/WhatsApp and four local suppliers who normally quote by phone or message. Include older phones, limited English confidence and different levels of typing comfort. Record these characteristics rather than assume all suppliers have the same needs. This sample can expose problems; it cannot establish market-wide adoption or savings.

Use fictional suppliers, rates and orders in an operator-prepared isolated test workspace on a verified revision. Preserve owner/member permissions and private supplier scopes. Prepare an answer key and two comparable baskets before the session. Do not mutate production, contact real businesses or create paid accounts. This document does not authorize those actions. Run the same tasks against a competitor only if an appropriate no-cost test environment is already available; otherwise mark **not tested**. This research pass did not start any app server or trial.

Allow a neutral two-minute introduction, then a 20-minute employee block and a 15-minute supplier block. Use the existing English-first UI without redesigning it during the trial. Record translation or reading assistance as help. Let participants attempt tasks unaided; give the same neutral hint when requested or after a recorded stall. Stop at the time limit without hiding unfinished work. Repeat the supplier quote with the second basket after the first attempt. When comparing with the participant's usual paper/message method, alternate method order across participants and use equivalent baskets to reduce practice effects. Simulate message text without sending it.

| Role/task | Scenario and observable completion |
| --- | --- |
| Employee: plan and draft | Use a prepared approved recipe, portions, known usable stock and confirmed arrivals. Identify shortages, then create/review an editable purchase draft. Correct quantities and units must match the answer key; no supplier is contacted. Include an unknown-stock case that should remain blocked. |
| Employee: suppliers and sharing | Review an existing contact and an unverified lead; explain what still needs checking. Prepare a private quote-link message, check the intended supplier and stop before Send. Use copy-link if no handler is available. Record recipient-check comprehension separately from sending, which is out of scope. |
| Supplier: first quote | Open a private test link without a QuotePlate account. Quote five items with quantity/unit, rate, availability, freight, delivery and supplied tax/term assumptions. Mark one item unavailable. Completion requires a correct submitted test quote, not merely opening the page. |
| Supplier: photo and repeat quote | Use a fictional printed-English price photo with one ambiguous unit and one conflicting rate. Review/correct matches and preserve an existing manual rate. Repeat with matching prior prices, verifying current quantities and terms before submission. Count wrong suggestions separately from errors remaining after review. |
| Employee/owner: compare and award | Compare two preloaded offers: one has a lower item rate but freight; the other has incomplete coverage. Identify the complete delivered-cost comparison and missing terms; an owner records the specified whole/split award. Do not expect a member to bypass owner permission. |
| Employee: delivery exception | Record a partial delivery with a rejection, replacement and entered invoice discrepancy against the award. Find the remaining quantity and claimed/received/outstanding credit. Completion matches the cumulative answer key; recorded credit is not proof of bank settlement. |
| Supplier: private workspace | Confirm a fictional business declaration, acknowledge the awarded order and disagree with a test delivery check using a note. Explain that an estimate is not an order and that declarations are not independent verification. Confirm visible records belong only to this test supplier. |

Public Google signup, shopping-list/invoice assistance and website-contact review are now implemented and have passed local checks; see the [release validation report](../qa/2026-09-11-procurement-gaps.md) for deployment evidence. Include these additional participant tasks: create a workspace with an external verified Google account; turn a printed five-item list into a purchase without a menu; correct an ambiguous row; review website contacts without overwriting an existing number; apply invoice billed values while entering physical receipt counts separately. None of these participant trials has been run.

## Measures and blank recording sheet

Measure the complete task, including review, corrections, device loading and handoffs. Record setup time separately so a prepared test workspace does not hide onboarding work.

| Measure | Definition |
| --- | --- |
| Time | Seconds from task instruction to correct saved/submitted result, or to stop/timeout. Record active work, waiting and setup separately. For quote turnaround, distinguish supplier entry time from elapsed time waiting for a response. |
| Error | Count incorrect/missing required fields and wrong decisions against the answer key; distinguish caught/corrected errors from errors remaining in the final record. Flag wrong recipient, exposed private data, wrong unit/quantity, incorrect total or wrong award as critical. A blocked unsafe action is not a successful procurement task. |
| Help | Count participant requests, moderator hints, translations/read-aloud assistance and takeovers separately. Record where each occurred. A moderator-completed task is not unaided completion. |
| Completion | Per task: correct unaided, correct assisted, incomplete/timeout, abandoned, or unavailable to test. Compute unaided and assisted rates using all attempted tasks as the denominator; list unavailable tasks separately with reasons. |
| Repeat effort | Compare first and repeat quote time, final errors and help for the same participant. Report the paired difference with basket/context details, not an extrapolated saving. |

| Participant code / role | Device, network, English/typing comfort | Task / method / revision | Setup / active / waiting / total seconds | Corrected / final / critical errors | Requests / hints / translation / takeover | Completion / stop reason |
| --- | --- | --- | --- | --- | --- | --- |
| Not run | — | — | — | — | — | — |

Report counts and denominators, individual failures, median/range of completed-task times and timeouts separately. Do not average only the fastest successful users or merge assisted with unaided results. Report whether a missing answer was caused by UI, supplier knowledge, connectivity or unavailable product access. A short debrief asks participants to explain what was sent/saved, who can see it, and what would stop them using it tomorrow.

Before recruitment, agree task-level acceptance targets with the parent project owner. Proposed minimum safety gate: no unresolved critical data/recipient/award errors in the trial; any observed exposure stops that scenario for investigation. This is a proposed gate, not a passed test. Prioritize repeated stalls and assisted-only completion for refinement, then retest the affected tasks. No conversion, time-saving, error-reduction or savings percentage is claimed until measurements exist.

## Zero-paid-integration costs and limits

**Zero paid integration means the documented workflow does not require purchasing a messaging, OCR or search API. It does not mean zero operating cost, unlimited capacity or guaranteed availability.** The following primary sources were visited on 11 September 2026. Provider pages can change; no provider account, billing configuration or actual invoice was inspected.

| Component | Evidence and cost boundary | Operational limit / fallback |
| --- | --- | --- |
| Manual WhatsApp sharing | WhatsApp's [click-to-chat help](https://faq.whatsapp.com/5913398998672934/?locale=ko_KR) describes prepared text and recipient selection. The retrieved page body was English despite the locale parameter; the en_US URL failed retrieval. QuotePlate's README documents a person reviewing/sending through their own account, without a Business Platform integration. | Phone/data and staff time remain. Opening the handler is not sending or confirmed delivery; in-chat replies do not populate quotes. Copy the private link when a handler is unavailable. |
| Automated WhatsApp boundary | Meta's [Business Platform pricing](https://whatsappbusiness.com/products/platform-pricing/) describes per-delivered-message pricing by market/category, with service-window/free-message exceptions. | These rules concern the separate API product, not QuotePlate's manual share control. Do not infer that automated reminders would be universally free or quote an India fee without the applicable rate card. No automated messaging is part of this scope. |
| Supplier photo OCR | [Tesseract.js](https://github.com/naptha/tesseract.js) is Apache-2.0 licensed and supports browser execution/local copies. The README documents bundled local processing and review before prices are used, with no supplier photo upload or paid OCR call. | Browser memory/CPU, initial asset bandwidth and review effort remain. The library does not itself support PDFs; its broad language support does not establish QuotePlate handwriting, regional-language or invoice accuracy. Use pasted text or manual entry when recognition fails. |
| Nearby area lookup | [Photon's maintainers](https://github.com/komoot/photon#demo-server) allow reasonable public-demo usage but warn of throttling/bans and give no availability guarantee. | No documented numerical request entitlement is inferred. Existing caching/rate limits reduce demand but cannot guarantee capacity. Use known contacts or external searches if unavailable; self-hosting would require infrastructure and operator effort. |

Review public leads; missing contacts/coverage are expected limitations. |
| Optional combined website search | Google's [Search Engine overview](https://developers.google.com/custom-search/docs/overview) lists a free, ad-supported Standard Search Element. The direct update URL returned HTTP 429 during this visit. | QuotePlate documents six supplier domains and an optional engine ID; this fits the domain-count boundary, but actual engine eligibility/configuration was not checked. Do not apply JSON API allowances or promise unrestricted Google search. External searches remain available without the embedded engine; results are not automatically verified/imported. |
| Hosting and storage | [Netlify's current pricing](https://www.netlify.com/pricing/) lists a Free plan with a 300-credit monthly limit; credits cover categories including production deploys, compute, bandwidth and web requests. This is a published plan, not evidence of QuotePlate's actual subscription. | No restaurant/user capacity follows from a credit count. Database, backups, temporary menu transfers, OCR/media downloads, monitoring, domain, support, device and connectivity costs need their own usage/account evidence. Existing account terms may differ. No zero-total-cost claim or monthly estimate is supported. |

Cost record for a future trial: record hosting plan and measured credit/compute/bandwidth use, database/storage/backup usage, any domain allocation, staff setup/review/support minutes and participant connectivity constraints. Report missing billing data as **unknown**, not ₹0. Keep staff time separate from provider charges; do not invent hourly rates. No paid integration was purchased, configured or required for this documentation task.

External website contacts remain leads requiring source review and manual confirmation. This note does not establish extraction completeness, business verification or permission to message. Existing manual sharing and private tenant/supplier access remain the operating boundaries.
