# Supplier collaboration backend

`service.ts` owns portal grants, restaurant authorization, public projections, response history and demand selection. `http.ts` supplies the fixed routes in the vendor collaboration plan. `types.ts` is the shared UI contract.

- Portal tokens use their own digest purpose and `SupplierPortal` resolver. The resolver returns tenant and portal IDs only. The application role then enters tenant RLS, locks the tenant/supplier/grant, and checks the current digest, revocation, expiry and active flags both before and after the operation. Links use `/supplier-portal#token=…`. Quote grants are independent.
- Members can read restaurant views; active owners alone rotate/revoke and share/withdraw. Creation and revocation use same-origin JSON `{}`. No message is sent automatically.
- Public snapshots include at most 30 latest invited non-draft orders and 30 future, nonwithdrawn, nonconverted estimates. Selected orders expose only the supplier's own accepted allocations and promised date. Closed, unselected orders expose no award items. Other suppliers' quotes, allocations, totals and rationale never enter the response DTO.
- `PortalOrder.version` is the collaboration version, initially 1, not the procurement request version. Responses serialize against the supplier and order/award locks. A receiving fingerprint includes only this supplier's immutable allocations and complete current receiving record. Receiving edits invalidate the old response without deleting it.
- Up to 50 acknowledgement/response revisions are retained per supplier/order, within 128 KiB. Further writes fail with 409 rather than discarding history. Each accepted mutation also creates a bounded audit event. Notes permit 1,000 characters and ordinary textarea whitespace; `needs_change` and `dispute` require explanations. Evidence references permit 200 single-line characters.
- Demand mutations lock the saved plan and require its exact reviewed version and explicitly selected shortage keys. Quantities are recomputed from saved inputs. Only names, purchase quantities, units and the five reviewed specification text fields are stored. URLs, thumbnails, unknown specification fields, plan names, recipes, stock and prices are excluded. Up to 100 selected items fit within 128 KiB. Past-service and converted plans cannot be shared. Changed plan versions mark old snapshots stale; withdrawn, converted and past-service estimates are hidden.
- HTTP bodies are limited to 16 KiB. Independent client and portal-grant rate buckets each allow 120 requests per 15 minutes. Every response is private/no-store. The HttpOnly, SameSite=Strict cookie is scoped to `/api/public/supplier-portal`; HTTPS/production cookies are Secure. Failed exchanges and unavailable grants clear it.

Migration `20260907000200_supplier_collaboration` creates the three tables with tenant-composite foreign keys, forced RLS, bounded JSON checks, indexes, minimal runtime privileges and read-only backup grants. Readiness and restore checks include the new tables and eighth private resolver. Tests cover real runtime-role PostgreSQL behavior, queued grant invalidation, mixed-supplier privacy, history/version conflicts, demand lifecycle, schema drift and cross-owner restore.
